`solution.sh <input-file>` — the starter is delivered as `solution.sh`; repair it in place.

## Starter (also in fixtures/S10.md)

```bash
#!/bin/bash
count=$(grep "ERROR" "$1" | wc -l)
echo "$count"
```

## Frozen prompt (submit to Pi)

The Bash script below is meant to print the number of lines of the file named by its first
argument that contain the literal uppercase substring `ERROR`, but it has a serious defect: when
the file is missing or cannot be read, the error is swallowed inside the pipeline and the script
wrongly prints `0` and exits successfully. Repair it so that a missing or unreadable input file
produces a diagnostic on stderr and exit status 2 with nothing on stdout, while a readable file —
including an empty one or one with no matches — still prints the correct count followed by a
newline and exits 0. The counting must remain a literal substring count, case-sensitive. You may
keep the pipeline or replace it with any other valid implementation. Keep the same single-argument
interface and the file name `solution.sh`.

```bash
#!/bin/bash
count=$(grep "ERROR" "$1" | wc -l)
echo "$count"
```

## Acceptance checks

- Counts identical to S06's on all counting fixtures (substring, case-sensitive, multiple per line
  counted once).
- Empty file → `0`, exit 0; no-match file → `0`, exit 0.
- Missing/unreadable input → exit 2, **empty stdout**, nonempty stderr (the starter fails exactly
  here: prints `0`, exits 0).
- Input byte-identical afterwards.
