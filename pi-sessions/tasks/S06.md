# S06 — Count literal `ERROR` lines · v1

Lineage: shares a template with D05 and S10 (development pool; excluded from the final test set).

## Invocation

`solution.sh <input-file>`

## Frozen prompt (submit to Pi)

Write a Bash script that reads the file given as its first argument and prints the number of lines
that contain the character sequence `ERROR` somewhere in them — uppercase, case-sensitive, as a
literal substring, with no special meaning given to any other characters on the line. Print only
the count followed by a newline. A file with no matches, or an empty file, is a success that
prints `0`. If the argument is missing, or the file does not exist or cannot be read, print a
diagnostic to stderr, write nothing to stdout, and exit with status 2. Do not modify the input.

## Acceptance checks

- Correct counts on fixtures with: multiple matches per line counted once, `ERRor`/`error` not
  counted, `ERRORS` and `XERRORX` counted (substring rule), empty file → `0`, no-match file → `0`.
- Lines with leading dashes/odd bytes counted normally.
- Missing file, unreadable file → exit 2, empty stdout, nonempty stderr.
- Input byte-identical afterwards.
