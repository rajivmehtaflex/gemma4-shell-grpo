## Frozen prompt (submit to Pi)

The Bash script below is a broken literal-search tool: it should print every line of the file
named by its second argument that contains the search term given by its first argument, treated as
a literal substring — never as a regular expression. Repair it so that: the term is matched
literally, so characters like `.`, `*`, and `[` have no special meaning; a term beginning with a
dash, such as `-n`, is treated as data and never as an option; an empty or missing term, or a term
containing a newline, is rejected with a diagnostic on stderr and exit status 2; a missing or
unreadable input file is also exit 2; matching lines are printed verbatim; the exit status is 0
when at least one line matches, exactly 1 when the file was read fine but nothing matched, and 2
only for genuine errors. Keep the same two-argument interface and the file name `solution.sh`.

```bash
#!/bin/bash
pattern="$1"
file="$2"
grep "$pattern" "$file"
```

## Acceptance checks

- Literal matching: `a.b` matches only `a.b` (not `aXb`); `*`, `[x]` treated literally; case-sensitive.
- Term `-n` searched as data (lines containing `-n` printed; no line-numbering side effects).
- Term `ERROR` on a no-match file → exit 1, empty stdout; match file → exit 0, lines printed.
- Empty term / missing term / term with embedded newline → exit 2, nonempty stderr.
- Missing/unreadable input → exit 2.
- Input byte-identical afterwards.
