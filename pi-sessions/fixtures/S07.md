# S07 fixtures · v1

Acceptance is **parse-equivalence**: an independent RFC-4180 parser reads the input and the
output; every output row's `id`/`name` values must equal the input's, in order, with header
`id,name` and LF endings. String-comparison against one fixed quoting style is deliberately NOT
the check.

## F-S07-main

Input (literal CSV; quoted fields contain commas, doubled quotes, and embedded newlines):

```
id,name,amount
1,alice,10
2,"bob, jr",20
3,"say ""hi"" now",30
4,"multi
line name",40
5,,"50"
```

Expected parsed output rows: `(1, alice)`, `(2, bob, jr)`, `(3, say "hi" now)`,
`(4, multi\nline name)`, `(5, <empty>)`. Header `id,name`. Five data rows, same order.

## F-S07-empty-body

Input is only the header `id,name,amount` → output is only the header `id,name`, exit 0.

## Error fixtures (each: exit 2, empty stdout, nonempty stderr, input unchanged)

- **F-S07-missing** — file does not exist.
- **F-S07-unreadable** — mode `000`.
- **F-S07-bad-header** — header is `id,name,value`.
- **F-S07-not-utf8** — file contains a `0xFF` byte.
- **F-S07-noargs** — no arguments.
