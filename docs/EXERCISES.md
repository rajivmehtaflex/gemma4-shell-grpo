## Scoring contract (frozen before any exercise acceptance)

- **Statuses.** Each fixture execution is `ok`, `invalid_script`, `runtime_error`,
  `resource_limit`, or `infrastructure_error`. Empty/non-UTF-8/NUL or `bash -n`-failing
  scripts are `invalid_script` before any fixture runs. A nonzero exit where success was
  expected is `runtime_error` (fixture score 0). OOM kill, host timeout, or output over the
  cap is `resource_limit` (fixture score 0). Specified nonzero exits (the exit-2 / exit-1
  error fixtures) are successful executions judged by checks, never runtime failures.
- **Aggregate precedence.** First present in `infrastructure_error > invalid_script >
  resource_limit > runtime_error > ok`. Thus `[ok, runtime_error]` → `runtime_error` and may
  earn partial reward; `[ok, infrastructure_error]` → unscorable.
- **Retry protocol.** A genuine infrastructure error retries the exact saved script/fixture
  up to two additional times (fresh fixture instance built from the same seed). If retries
  fail, the whole group is invalidated and the run halts for repair — task score `null`.
- **Task score.** With every fixture scored: any task-critical violation → `0`; no required
  functional progress on the declared progress fixtures → `0`; otherwise the declared
  weighted fixture average capped at 1. Preservation is a gate: it can zero a task, never
  earn reward. Full reward requires every required check on every fixture to pass.
- **Fixture score models** (declared per task in `diagnostics.jsonl`):
  - `simple`: all-or-nothing on exact stdout + exit convention + full-tree preservation
    (failure fixtures check exit code, empty stdout, nonempty stderr, zero mutation).
  - `copied_fraction`: fraction of required files present at the destination with exact
    bytes; extra destination entries, source mutation, or a missing destination directory
    are task-critical.
  - `moved_fraction` (S03): placed = present in archive with original bytes **and absent
    from the source**; unselected entries must be untouched.
  - `text_output` (D03/S05): `0.8 × totals_fraction + 0.2 × order`; every-total-correct but
    unsorted scores 0.8 on that fixture; fabricated keys are task-critical.
  - `csv_roundtrip` (S07): independent parser comparison; structural failures (unparseable
    output, wrong header, CR bytes, wrong row count) cap the score below full.

## Worked boundary cases (required by PLAN.md)

1. **No-op vs empty input.** Every task declares an empty/none fixture that a correct script
   legitimately passes with zero work (e.g. D01 `d01-empty` → `0`), but the reward gate
   requires progress on the declared nonempty fixtures. The `wrong-noop.sh` script
   (`exit 0`) therefore scores 0 on every task, and the D01 `wrong-hardcode.sh` (`echo 0`)
   passes `d01-empty`/`d01-decoys` yet scores 0 because it fails both progress fixtures.
2. **D03 totals correct, output unsorted.** `wrong-unsorted.sh` produces every correct total
   in first-seen order; each scored fixture yields `0.8`, task score ≈ 0.86 — partial, never
   full.
3. **D04 copies correctly but mishandles invalid arguments.** `wrong-no-validation.sh`
   passes `d04-main` (fraction 1.0) and `d04-empty-src`, but on `d04-invalid-*` fixtures it
   exits 0 where a nonzero exit is required — those fixtures score 0 without mutation, task
   score 0.55. A variant that *mutates* (creates a file at the missing destination path)
   trips the task-critical preservation gate → 0.
4. **Accepting missing input is critical (D05/S06/S10).** The D05/S10 starter pipelines
   (`grep ERROR $1 | wc -l`) print `0` and exit 0 on a missing file: the runner marks the
   fixture failed and the task-specific verifier records a task-critical violation
   (`missing_input_accepted`) → task reward 0.
5. **Copy-instead-of-move (S03).** Files appearing in the archive while still present in the
   source do not count as placed; `wrong-copies.sh` scores 0.
6. **Case-sensitivity and substring traps** (D05/S06/S10): `error`/`ERRor` never count,
   `ERRORS`/`XERRORX` do; a `grep -w` variant loses `ERRORS`/`XERRORX` (partial only).
7. **Exit-2 discipline** (S-tasks): missing arguments, missing/unreadable inputs, and every
   specified invalid destination must exit exactly 2 with empty stdout and nonempty stderr
   and zero mutations — verified by full-tree hash before/after.

## Wrong scripts (frozen set per task)

Every task ships `wrong-noop.sh` (`exit 0`), `wrong-empty.sh` (empty file →
`invalid_script`), a hard-coded or starter-derived script, and one or two task-specific
semantic errors (unquoted parsing, recursive overreach, symlink following, wrong sort order,
case-insensitive match, missing validation, exit-discipline loss, dotfile loss, off-by-one
slicing, first-match instead of argmax). Declared outcomes (`zero` = task reward 0, `partial`
= reward strictly between 0 and 1) are asserted by the acceptance harness; the frozen set
lives next to each task's `reference.sh` / `alternate.sh` under
`data/examples/scripts/<TASK>/`.

## Acceptance protocol

`scripts/acceptance.py` (Codespace only — the grading image does not exist on the dev host)
runs, per task: reference ×3, alternate ×3, `wrong-noop.sh` ×3, remaining wrongs ×1 — each a
full `grade_script` execution with contract validation. Reference/alternate/no-op results
must be identical across repeats modulo timing and artifact paths. The harness emits
`summary.json` + `summary.md` and exits nonzero on any unmet expectation. The group seed per
task is derived deterministically (`sha256("phase1-acceptance:<TASK>")`); GRPO groups derive
per-fixture seeds from the supplied group seed via `derive_fixture_seeds`.
